# Debug tool: RAM map and warp mechanism

Tools: `tools/debug/warp.lua` (driver), `scenes.lua` (scene list), `warp.py` (runner, regen-all), `call.lua`
(redirect a call into any function, e.g. name entry),
`fileload.lua` (file-load log probe), `maps.txt` / `files.txt` (map and file tables), `mkmaps.py`.
All addresses are RAM (EXE loaded at 0x80010000). **verified** = warp test with a proof shot in
`work/qa/warp/<scene>/scene.png`, regenerated by `python -X utf8 tools/debug/warp.py --all`.

## Files (verified: fileload.lua log matches what is on screen)
- `cd_load(index a0, dest a1, ?, mode a3)` at 0x8001AC54. Index = MMPS_CD.SFS entry = EXE path table
  0x8006FB94 (`tools/debug/files.txt`). So the game **does** read files through MMPS_CD.SFS (in RAM at 0x8008F710):
  a rebuild that moves or resizes a file must rewrite it (phase 3).
- Boot: SND00/01, HUDTIT (Hudson logo), FONT, EVTTIT (title). New Game: EVTOP (intro).
- SHOP.MMB (file 3) is MIPS code loaded to 0x80155000 by the shop entry functions (0x80020C78, 0x80034EE8 ...).

## Main loop (verified)
- 0x80019128; state s16 at **0x800847E0**, dispatched through the table at 0x80010050 (index state+1):
  -1 quit, 0 load map, 1 battle (0x800192A8), 2 field (0x8001968C -> field loop 0x8002FDE4),
  4 minigame (selector u8 0x800846E8), 5 event (selector u8 0x800847DF), 7 return to map, 8 0x8004F7EC.
- Field loop 0x8002FDE4 runs while u16 **0x800846FA** != 0; set it 0 to drop back to the main loop.
- `goto_map(map, x, y, dir, mode)` 0x8001A4D8 writes {1, map, x, y, dir} to 0x80094A50, map to **0x800847D6**,
  state 0. warp.lua writes the same and clears 0x800846FA (or replaces the New Game intro: state 5 + event 6).
- `load_map(n)` 0x8002D714; map table 0x800729FC (36 B/entry: u16 file index ... u16 room), second table
  0x80077FE4 (16 B: overlay init, EXE init, goto_map callback, s16 parent map). 560 maps: Z00 = overworld
  (map 0), SMAP towns 1-35, HMAP interiors (HMAP00-12 are the per-town shop/inn interiors, room = town),
  DMAP dungeons, NMAP/OMAP/JMAP/WMAP areas. `tools/debug/maps.txt`.
- Last town (respawn) 0x800918FE; script command handlers near 0x80032B20 (start_minigame 0x80032B7C,
  start_event 0x80032B98).

## Battles (verified: random battle on the overworld)
- The field loop sets state 1 when `0x80045670(terrain, ?)` rolls an encounter; 0x8004540C sets up the group.
  Battle loads BBxxx (background) + BMxxx (monster) + FBTL.BIN. A fixed-group warp is not built yet
  (would need an exec hook on 0x8004540C a0, --debugger).

## Inventory, techniques, name entry (verified, phase 5)
- Inventory: 6-byte slots from 0x8009133A (u16 item id, 0xFFFF = empty, then 4 bytes), ~96 slots; found by a RAM
  diff around a purchase. Scene `menu_items` pokes ids 1-24. Item names are not generally FONT_6:060+i:
  `0x800DEF20(id)` reads the name index at +6 of the 20-byte record at `0x800E1510 + 20*id`.
  For example, Map is item 264, whose name is FONT_6:287; item 227 is Pacific Saury, not Map.
- Techniques: 9 learned bits per party member at 0x800FE3A8 + 2 * member (byte 2m bits 0-7, byte 2m+1 bit 0);
  read by the flag check 0x800FC0C8 (flags 0x10E + 9 * member + k), counted by 0x800DF5A4. Scenes `menu_techs`,
  `battle_lists` hold 0x1FF there (scene field `hold` = poke every frame).
- Name entry: 0x800DC3D0(a0 = mode), called only from map overlays (OMAP00 room 0 fortune teller, SMAP16, WMAP08,
  WMAP15, HMAP2606). Reach it with `tools/debug/call.lua` (redirects the next call of AT into CALL, keeping $ra):
  `emu.py rom/<cue> --debugger --state-in work/states/map_36.sstate --script tools/debug/call.lua --var AT=0x8003B284
  --var CALL=0x800DC3D0 --var A0=1 --route-str "6 up;20 -;6 circle;30 -;6 circle;200 -"` (talk to the NPC north of
  the start; the JP map_36 state has him in place). Redirecting the "examine" message instead hung the emulator.
- Battle command menu: `battle_long` / `battle_lists` (god mode, circle every 100 frames) reach it on round 2; the
  first round can be an ambush (no commands). Marker build: menu at ~f5440 with --var SETTLE=6000 --state-every 40.

## Companions, string log, overlay calls (phase 7 width work)
- Party: u16 at 0x80091310 + 2 * id != 0 puts character id with Momotaro (ids 4-13 = Dog .. Jizo; list 0x8007ACCC,
  check 0x8003FB64). Companion skills unlock by bits of u16 0x8009195C (0xFFFF = all). Scenes `orders_party`,
  `town_warp` (pheasant's list in town 2), `enon_world` (Enon's direction line on the overworld).
- `tools/debug/strlog.lua` (--debugger) logs the first fetch of each FONT_5/6/7 string through get_string
  0x8003D944 with its caller: which screen draws a label. `tools/debug/hold.lua --var "HOLD={{addr,size,v}}"`
  rewrites RAM every frame in a run from a savestate.
- `tools/debug/xref.py ADDR` finds lui/addiu pairs and data words that hold an address (window callbacks ->
  descriptors, docs/re/windows.md); `tools/debug/imm.py FILE BASE N..` lists immediate index loads in any code file.
- Elevator (maps 309-314, HMAP26/2606/2607:65 overlay at 0x80168000): reach the floor list with call.lua
  AT=0x8003B284 CALL=0x801681E4 from a map-309 state, route menu > Check (`circle; right; circle`), and hold
  0x80084786 = 0x200 (`work/qa/m8_elev3`).
